# دليل إجراءات استعادة الحساب والمصادقة الثنائية (Account & 2FA Recovery Procedures)
**تاريخ الوثيقة:** 14 نوفمبر 2026  
**المشروع:** منصة د. جلال أحمد للاستشارات (`galal-web`)  
**المسار:** `docs/ACCOUNT_RECOVERY.md`  
**الحالة:** معتمد للإجراءات الأمنية (Security Operational Procedure)  

---

## 1. نظرة عامة والهدف

تعتمد المنصة تقنية التحقق بخطوتين عبر معيار **RFC 6238 TOTP** لحسابات المعالج (`counselor`) وإدارة المنصة (`admin`) لحماية السجلات السريرية والبيانات الحساسة. يوضح هذا المستند الإجراءات المعتمدة في حال فقدان هاتف المشرف أو المعالج أو تعطل تطبيق المصادقة (Google Authenticator / 1Password).

---

## 2. المسار الأول: الاستعادة الذاتية عبر أكواد الاسترداد (Recovery Codes)

عند تفعيل التحقق بخطوتين لأول مرة، يُزود النظام المستخدم بحزمة من **10 أكواد استرداد أحادية الاستخدام (Single-Use)** بصيغة `XXXX-XXXX`:

1. **الآلية الأمنية للتخزين:**
   - تُخزن أكواد الاسترداد في قاعدة البيانات بصيغة **مجزأة أحادية الاتجاه (SHA-256 Hashes)** مع تجزئة فريدة، ولا يمكن للنظام أو موظفي الدعم استرجاع الكود الأصلي.
2. **خطوات الاستخدام:**
   - في صفحة تسجيل الدخول، عند المطالبة برمز الـ 2FA، يختار المستخدم: *"استخدام كود استرداد بديل"*.
   - يُدخل المستخدم أحد الأكواد العشرة المطبوعة أو المحفوظة لديه.
   - فور التحقق بنجاح، يُحذف الكود فورياً من قاعدة البيانات (تدمير أحادي الاستخدام).
   - يُطلب من المستخدم فور الدخول إعادة تعيين مفتاح الـ TOTP وتوليد حزمة أكواد استرداد جديدة.

---

## 3. المسار الثاني: الاستعادة الطارئة عبر المشرف التقني وقاعدة البيانات

في حال فقدان الهاتف وكافة أكواد الاسترداد العشرة معاً:

> [!WARNING]
> لا يُقبل أي طلب لإلغاء التحقق الثنائي عبر البريد الإلكتروني أو المحادثات الفورية غير الموثقة لتفادي هجمات الهندسة الاجتماعية (Social Engineering).

### خطوات التحقق اليدوي الصارمة:
1. **التحقق من الهوية:** يتواصل المعالج شخصياً مع المشرف التقني المعتمد للمنصة عبر اتصال مرئي موثق أو مقابلة مباشرة للتحقق الصارم من الهوية.
2. **إجراء الإلغاء عبر قاعدة البيانات الآمنة (Break-Glass Database Query):**
   - يدخل مهندس النظام الحاصل على صلاحية الوصول المباشر إلى قاعدة Supabase.
   - يُنفذ الاستعلام التالي لتعطيل الـ 2FA مؤقتاً لحساب المعالج وتعيين علم إجبار تغيير المفتاح:
   ```sql
   -- فك الارتباط المؤقت لحساب المعالج
   UPDATE public.profiles
   SET 
       totp_secret = NULL,
       totp_enabled = FALSE,
       recovery_codes = '[]'::jsonb,
       must_reset_password = TRUE
   WHERE email = 'counselor@galalahmad.com' AND role = 'counselor';

   -- تسجيل عملية الاستعادة الطارئة في سجل التدقيق السريري
   INSERT INTO public.clinical_audit_logs (
       actor_id,
       actor_role,
       action,
       target_resource,
       metadata
   ) VALUES (
       'system-emergency-override',
       'admin',
       'EMERGENCY_2FA_RESET',
       'counselor@galalahmad.com',
       '{"reason": "Lost device - verified identity via direct protocol"}'::jsonb
   );
   ```
3. **تسجيل الدخول وإعادة التأسيس الفوري:**
   - يسجل المعالج دخوله باستخدام كلمة المرور.
   - يُلزم النظام المعالج فورياً بإعادة مسح رمز QR جديد وتفعيل المصادقة الثنائية وتنزيل حزمة أكواد استرداد جديدة قبل السماح له بالوصول إلى لوحة التحكم والملفات السريرية.
